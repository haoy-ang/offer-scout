# 技术简历写法参考（示例素材）

> 本文件是跑通 RAG 链路的示例素材，请替换成你自己的总结。

---

## 项目经历的四要素

一条合格的项目描述，应该能回答四个问题：

1. **是什么**：一句话说清项目定位，别用"XX 管理系统"这种看不出技术含量的名字
2. **你做了什么**：你的具体职责，用动词开头（设计、实现、重构、优化）
3. **技术难点是什么**：这是最重要的部分，也是面试官唯一会深挖的地方
4. **结果如何**：尽可能量化——接口耗时、并发能力、数据量、效率提升

写成这样：

> 负责 XX 模块的设计与实现，通过引入本地缓存 + 批量查询，将列表接口 P99 耗时从 800ms 降到 120ms；
> 使用 ReAct 模式实现自主规划智能体，支持多步工具调用与流式输出。

而不该是这样：

> 参与了项目的开发，使用了 Spring Boot 和 MySQL，实现了增删改查功能。

## 常见问题与改法

**问题一：技术栈堆砌，没有细节**
改法：挑 2-3 个最有把握的技术点展开写，每个都准备好吃追问。

**问题二：只写"用了什么"，不写"为什么用"**
改法：补上选型理由。哪怕理由不完美，也比没有强——面试官想听的是你的思考过程。

**问题三：没有量化**
改法：实在没有线上数据，就用本地压测数据、生成的数据量、代码行数减少比例等。

**问题四：项目全是"跟教程做的"**
改法：不要隐瞒学习来源，但要在原基础上做出**自己的改动**，并想清楚改动的理由。
面试官反感的是"说不清细节"，不是"有学习经历"。

## 面试官会怎么追问项目

以"用了 Redis 做缓存"为例，典型的追问链条：

1. 为什么用 Redis？不用行不行？
2. 缓存的是什么数据？key 怎么设计的？
3. 过期时间设多少？为什么？
4. 缓存穿透、击穿、雪崩怎么处理的？
5. Redis 挂了怎么办？降级策略是什么？
6. 缓存和数据库怎么保证一致性？延迟双删了解吗？

**判断标准**：能顺着一条线答到第 5、6 层，才算真的做过。答到第 2 层就卡住，面试官会认为是"跟着教程抄的"。

## 技能清单怎么写

不要写"精通"，除非你确实能扛住深挖。推荐用：

- **熟练**：能独立开发、能讲清原理、能排查常见问题
- **熟悉**：用过、理解核心概念、能查文档解决
- **了解**：知道是什么、大概怎么用

按"求职方向优先"排序。投 Java 后端，就把 Java 相关写在最前面，前端往后放。

## 时间线节奏（以 2027 届为例）

| 时间 | 该做什么 |
|---|---|
| 大二暑假 | 打基础：Java 语法、数据结构、算法入门 |
| 大三上 | 做 1-2 个能讲透的项目，开始刷八股 |
| 大三下（2026 春） | **投 2026 暑期实习**——校招最稳的通道 |
| 大三暑假 | 实习，争取转正 |
| 大四上（2026 秋） | 秋招，同时补投其他公司 |

**关键提醒**：暑期实习的投递时间比很多人想象的早，通常在前一年的 3-5 月就开始了。
错过这条线，秋招会明显更被动。
