# 技术简历写法精要（校招 / 应届生向）

本文件整理自多份简历写作资料，已去除重复与口水内容，只留可直接执行的写法与判据。适用于 Java 后端方向的校招投递。

---

### 简历的整体结构与版式

应届生推荐结构，从上到下依次排列：
1. 个人信息（含求职意向、联系方式）
2. 教育背景
3. 项目经历（校招最重要的一栏）
4. 实习经历
5. 技能清单
6. 荣誉奖项
7. 自我评价

校园经历（社团、学生会、竞赛）视情况加入，没有就不写，不要为凑栏目硬编。

版式规则
1. 一页纸为最佳；经历确实丰富最多放宽到 2–3 页。
2. 一律倒叙：最近、最相关的经历放最前。转方向投递时，把与目标岗位匹配度最高的那段挪到第一位。
3. 用从上到下的单栏流式模板，不要左右分栏；板块之间的边界要明显，不要让多个模块糊在一起。
4. 不要花哨配色和设计元素，简历是商务文件。可以用简单符号做分隔，但别标新立异。
5. 导出 PDF，不要用 Word——不同版本打开会错版，直接影响信息表达。
6. 每一段经历本身也要有层次：用分隔线、空行区分，关键信息加粗，避免变成一坨文字。

---

### 个人信息：写什么、不写什么

姓名
1. 写真名，不用昵称或网名。
2. 字号可以大于正文，放在最显眼的位置。

年龄与身高体重
1. 年龄一般不写，应届生或需要工作经验的岗位可写，格式为「年龄：xx 岁」。
2. 身高体重属个人隐私，除非岗位明确要求，否则不写。

证件照
1. 附专业照片，避免自拍和大头贴。
2. 非外企放照片，外企不放。
3. 拍法：专业照相馆、蓝底、穿正装；拍完一定要拿源文件，方便后续在电脑上使用。

电话与邮箱
1. 电话要常用且有效，求职期间保证畅通，别错过面试通知；格式便于阅读，如「138 0000 8000」。
2. 邮箱用专业地址，最好以姓名命名，例如 zhangsan@qq.com。QQ 邮箱可以改名，把纯数字账号改成姓名拼音，好记且美观。
3. 邮箱要写——企业的重要通知都走邮箱，比电话更容易漏。

地址与求职意向
1. 地址写到城市和省份即可。
2. 求职意向必须写清楚，避免 HR 看不懂你要投什么。错误写法是「开发工程师」，正确写法是「Java 后端开发工程师」。
3. 目标薪资：如果你会投很多家、岗位薪资跨度大、更看重平台机会，就不填。

---

### 教育背景

1. 写学校全名，不要简写；学校有名气可加 985 / 211 / 双一流等修饰。
2. 明确学位类型与专业（本科 / 硕士等）。
3. 写清起止年月；尚未毕业写预计毕业时间，如「预计 2027 年 6 月」。
4. GPA 高才写，可以带排名，例如「GPA 3.8/4.0（专业 top 5%）」。
5. 相关课程：应届生可以列与岗位相关的课程（数据结构、算法设计、数据库原理、操作系统、计算机网络）；有工作经验后不建议再列。
6. 荣誉证书只列有含金量的（国家奖学金、ACM 竞赛奖、CET-6）；低水平证书列上去反而拉低评价。
7. 多段教育经历按时间倒序，学历最高的放最上面；不重要或市场不认可的那段可以不写。

### 项目经历：数量、描述公式与写法对照

数量
1. 校招写 2 个能讲透的项目就够；社招标准是 3–4 个。数量不重要，能被深挖才重要。
2. 简历池里 85% 以上的学生写的是「某某商城」和「秒杀系统」，尽量换一个别人少写的方向。实在没有，写了也比空着强。

描述公式
每一条描述都要回答四件事：是什么、你做了什么、技术难点是什么、结果如何。
1. 是什么：一句话说清项目定位，别用「XX 管理系统」这种看不出技术含量的名字。
2. 你做了什么：用动词开头（设计、实现、重构、优化），写清你的具体职责。
3. 技术难点：这是最重要的部分，也是面试官唯一会深挖的地方。
4. 结果如何：尽可能量化——接口耗时、并发能力、数据量、效率提升比例。

写法的正面与反面
值得写的写法：负责 XX 模块的设计与实现，通过引入本地缓存 + 批量查询，将列表接口 P99 耗时从 800ms 降到 120ms。
不该出现的写法：参与了项目的开发，使用了 Spring Boot 和 MySQL，实现了增删改查功能。
判据：后一种写法等于什么都没说，本质就是「新增改查」。

### 项目经历：篇幅、真实性与时间线

长度与重点
1. 每个项目描述控制在 1–2 段，不要写成几百字的说明书。
2. 多写效果和难点，少写业务背景叙述——技术面试官不关心项目服务于什么业务。
3. 对与岗位匹配的重点项目，可以展开技术细节，这会让面试官看出真实水平。
4. 每个项目都要有难点与亮点，并写清你是怎么解决的，这是加分项。

真实性与准备
1. 不要撒谎。项目里提到的技术，一定要能讲清原理，否则不要写。
2. 写在简历上的东西必须是自己懂的，包括细节。

时间与相关性
1. 时间区间要连续，格式统一，不要出现空白或重叠；有空窗期就一句话解释（进修、家庭原因等）。
2. 用与目标岗位相关的关键词，既方便 HR 筛选，也方便通过系统的自动筛选（ATS）。
3. 如果你是转方向投递，简历上 60% 的经历应与岗位相关；与岗位无关的经历（如与投递岗位无关的社团职务）不要占篇幅。

### 技能清单

1. 分三档写，不要只写一档：
   - 熟练：能独立开发、能讲清原理、能排查常见问题。
   - 熟悉：用过、理解核心概念、能查文档解决。
   - 了解：知道是什么、大概怎么用。
2. 不要写「精通」，除非你确实能扛住深挖。写「精通」等于给自己挖坑——面试官会照着这栏展开提问。
3. 按求职方向排序：投 Java 后端，就把 Java 相关写在最前面。
4. 不可把专业名词写错；也不要堆砌关键词，写着混乱会让人觉得你思路不清晰。
5. 不知道、不熟悉的写「了解」就好，不懂装懂最致命。

---

### 自我评价

1. 控制在 3–5 句，简短有力。
2. 突出与岗位相关的专业技能，再补软技能（沟通、协作）。
3. 用数字最直观：「大三期间有 15 个月互联网实习经验」「运营自媒体期间从 0 积累 4600 粉丝」。
4. 避免空洞陈述，不要写「努力工作」「有责任心」这类谁都能写的词。
5. 内容要与所投岗位有关，不要写与岗位无关的经历。
6. 避免模板化，否则一眼就看得出是抄的。

---

### 命名、投递与作品集

1. 简历文件命名要让人一眼看出你是谁、投什么岗，格式如：姓名_应聘岗位_工作年限。
2. 每投一家公司都要针对该岗位调整简历内容，切忌所有公司和岗位都用同一份。改动不大，但 HR 看得出你上了心。
3. 作品集用于证明专业水平，可以是项目、文章、代码或设计。形式用链接、二维码或附件都行，关键是让 HR 方便看到——不要放在需要开会员才能下载的地方。
4. 设计类岗位另附作品集，电子版控制在 10M 以内，只挑精华；过杂反而提高淘汰率。

### 简历与面试的联动：简历是钩子，准备要主动

核心认知：简历写什么，面试官就问什么。所以简历是钩子——主动埋下你想被问、且已经准备好答案的点。

准备工作
1. 面试前把简历上的每个细节都捋一遍，特别是写上去的技术原理。
2. 面试前花半小时了解目标公司的业务和所用技术。嘴上说很想加入、却对公司一无所知，是非常减分的。
3. 先从较容易的面试开始练手；每次面试后做总结。

回答方式
1. 要主动扩展。被问「项目里用到什么技术」，除了说 Spring MVC、数据库常规技术，还可以带出 JVM 内存管理、缓存设计等你拿得出手的点。你不说，面试官就默认你只会基础的。
2. 找机会做延伸说明。被问「有没有用到一对多和多对多」，除了说基本知识点，还可以补一句你会根据需求设置 cascade 和 inverse，再用一个实际案例说明设计收益。
3. 不要把回答局限在「项目里做了什么业务、代码怎么写」——那等于把后续提问权交给面试官，会被牵着走。

### 简历与面试的联动：典型追问链

以「用了 Redis 做缓存」为例，面试官的追问会逐层加深：
1. 为什么用 Redis？不用行不行？
2. 缓存的是什么数据？key 怎么设计？
3. 过期时间设多少？为什么？
4. 缓存穿透、击穿、雪崩怎么处理的？
5. Redis 挂了怎么办？降级策略是什么？
6. 缓存和数据库怎么保证一致性？延迟双删了解吗？
判据：能顺着一条线答到第 5、6 层，才算真的做过。答到第 2 层就卡住，面试官会判定为「跟着教程抄的」。

### 常见扣分点汇总

1. 项目描述全是「实现了增删改查」，看不出技术含量。
2. 只写「使用了 XX 技术」，不写「解决了什么问题、效果如何」。
3. 堆关键词但讲不出细节，或项目浅显没有难度。
4. 技能清单写「精通」但被追问就答不上，或技能描述与实际回答明显不符。
5. 时间线有空白、前后矛盾，或后面的回答无法支撑简历上的描述。
6. 简历上 60% 的经历与所投岗位无关。
7. 用一份简历投所有公司。
8. 项目描述写了数百字却抓不住重点，或整个项目就是简单的新增改查。
